# 오류 분석과 학습 정리

Tensor 연산에서 발생한 오류를 입력 조건, 원인, 해결 코드, 확인 결과 순서로 정리했습니다. 결과는 제출 노트북에 저장된 출력을 기준으로 합니다.

## 1. 음수 인덱스의 범위

`t`의 shape은 `(2, 3)`입니다. 행이 두 개이므로 행 인덱스는 `0, 1` 또는 `-2, -1`을 사용할 수 있습니다. `t[-5]`는 존재하지 않는 행을 선택해 IndexError가 발생합니다.

```python
t = torch.tensor([[1, 2, 3], [4, 5, 6]])
print(t[-1])  # tensor([4, 5, 6])
```

음수 인덱스도 축의 길이 안에서만 사용할 수 있습니다. 먼저 `t.shape[0]`으로 행 수를 확인하면 범위를 판단할 수 있습니다.

## 2. 불리언 마스크의 길이

행이 2개인 텐서에 길이 3인 행 마스크를 적용하면 대상 축과 마스크의 크기가 맞지 않습니다.

```python
row_mask = torch.tensor([True, False])
print(t[row_mask])  # tensor([[1, 2, 3]])
```

이 경우 마스크는 첫 축의 행을 선택합니다. 원소별 조건인 `t > 3`과 행 선택용 마스크를 구분해야 합니다. 전자는 텐서 전체와 같은 shape을 만들고, 후자는 선택할 행 수와 길이를 맞춥니다.

## 3. reshape의 자동 크기 계산

`base.reshape(-2)`는 자동 계산 인자로 허용되지 않는 음수를 사용해 RuntimeError가 발생합니다. 자동 계산은 `-1`로 지정합니다.

```python
base = torch.arange(1, 7)
print(base.reshape(-1).shape)   # torch.Size([6])
print(base.reshape(2, 3))
# tensor([[1, 2, 3],
#         [4, 5, 6]])
```

원소 6개를 재배치하므로 변환 후 축 길이의 곱도 6이어야 합니다. 별도 예제의 `base12 = torch.arange(12)`는 `(3, 4)`로 변경합니다. 두 예제의 원소 수를 구분해 읽어야 합니다.

## 4. unsqueeze의 축 범위

1차원 텐서에 `unsqueeze(2)`를 적용하면 IndexError가 발생합니다. 1차원 입력에 축을 하나 추가할 위치는 `0, 1` 또는 `-2, -1`입니다.

| 입력 | 연산 | 결과 shape |
|---|---|---|
| `(12,)` | `unsqueeze(0)` | `(1, 12)` |
| `(12,)` | `unsqueeze(1)` | `(12, 1)` |
| `(2, 3)` | `unsqueeze(0)` | `(1, 2, 3)` |
| `(2, 3)` | `unsqueeze(1)` | `(2, 1, 3)` |
| `(2, 3)` | `unsqueeze(2)` | `(2, 3, 1)` |

같은 축 번호라도 입력 차원 수에 따라 유효 여부가 달라집니다. 축을 추가한 후 `squeeze(1)`을 사용할 때는 해당 축의 길이가 1인지 확인합니다.

## 5. 행렬 곱의 안쪽 차원

`A.shape=(100,128)`이고 `wrong_W.shape=(256,128)`일 때 `A @ wrong_W`는 실패합니다. 왼쪽의 열 수 128과 오른쪽의 행 수 256이 다르기 때문입니다.

```python
fixed_result = A @ wrong_W.T
print(wrong_W.T.shape)   # torch.Size([128, 256])
print(fixed_result.shape)  # torch.Size([100, 256])
```

이 예제에서는 전치로 계산 가능한 모양을 만듭니다. 실제 데이터에 적용할 때는 축이 의미하는 표본·특성의 방향도 함께 확인해야 합니다. 단순히 계산이 가능하다는 이유만으로 전치가 항상 올바른 해결은 아닙니다.

## 6. Softmax의 overflow

큰 logits를 바로 지수화하면 표현 범위를 초과합니다. 저장된 결과에서 `[1000, 2000, 3000]`의 직접 계산은 `[nan, nan, nan]`으로 나타났습니다.

```python
shifted = large_logits - np.max(large_logits)
stable = np.exp(shifted) / np.exp(shifted).sum()
# shifted: [-2000, -1000, 0]
# stable: [0., 0., 1.]
# 합계: 1.0
```

모든 입력에서 같은 상수를 빼면 지수의 공통 배율이 분자와 분모에서 상쇄됩니다. 최댓값을 빼면 가장 큰 지수 입력이 0이 되어 overflow를 피할 수 있습니다. 이 예제의 작은 확률은 부동소수점 표현에서 0으로 계산됩니다.

## 7. CUDA 환경의 제한

기존 실습 출력은 `torch.cuda.is_available() == False`, `torch.version.cuda is None`입니다. 따라서 CPU와 CUDA 텐서를 섞는 오류를 실제로 재현한 결과는 없습니다. 노트북에는 CUDA가 사용 가능한 경우에 실행하는 조건부 코드가 포함되어 있습니다.

CPU에서 확인한 연산 결과와 CUDA 환경에서만 확인 가능한 장치 불일치 문제를 구분했습니다.

## 8. 저장공간과 성능 해석

`expand`와 `repeat` 결과의 값은 같았지만 `data_ptr()` 비교는 각각 원본과 동일한 주소, 다른 주소로 나타났습니다. 이 실험에서는 값을 비교하는 것만으로 메모리 동작까지 판단할 수 없음을 확인했습니다.

백만 원소 제곱의 저장된 시간은 리스트 방식 49.8 ms, NumPy 방식 688 μs입니다. 단위를 맞추면 49.8 / 0.688 ≈ 72.4입니다. 이 비율은 해당 기록의 비교값이며 다른 PC의 속도를 보장하지 않습니다.
